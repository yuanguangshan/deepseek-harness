# dsh web 启动 token 持久化（手机/收藏夹登录一次搞定）

> 日期：2026-09-09 凌晨 ｜ 实现人：ZCode ｜ 状态：**已上线，3080/3081 双实例验证通过**

## 一、问题与原理

alpha.2 的 web 鉴权分两层（`packages/client/connection/src/browser-auth.ts`）：

1. **cookie 签名密钥**：持久化在 credentials 存储（`~/.dsh/.credentials.yaml`），cookie 有效期 30 天——这层本来就不丢。
2. **启动 token**（`?token=` 换 cookie 的那个）：`processLaunchToken()` 每次启动 `randomBytes` 纯随机，**且无任何 env/配置钩子**——每次重启后旧 token 链接全部失效。手机走 dsh.want.biz / dsh-dev.want.biz 时没法看日志拿新链接，所以「非常不便」。

cookie 按「访问域名（authority）」分别签发，手机收藏哪个域名就用哪个域名登录一次即可。

## 二、方案：DSH_WEB_TOKEN 环境变量 + 三处接线

dev 源码 `browser-auth.ts` 新增钩子：`DSH_WEB_TOKEN` 若为合法值（base64url、≥32 字符，即 128 位强度）则每次启动都接受它；未设置/非法则照旧随机（非法值打一条 warn）。

| 实例 | token 来源 | 消费方式 |
|---|---|---|
| **3081**（dev 构建） | `~/.dsh/run/dsh-web-dev.token`（0600，脚本首次自动生成） | `dsh-web-dev.sh` 的 `ensure_token` + `export DSH_WEB_TOKEN` |
| **3080**（官方 npm 包） | `~/.dsh/run/dsh-web.token`（0600） | LaunchAgent plist `EnvironmentVariables.DSH_WEB_TOKEN` + **官方包热修补丁** |

**官方包补丁**：`~/.dsh/patch-web-token.sh` 往
`/opt/homebrew/lib/node_modules/@deepseek-ai/dsh/node_modules/@deepseek-ai/dsh-client-connection/lib/index.js`
的 `processLaunchToken` 里注入同款 env 判断（幂等，备份 `index.js.bak-web-token`，回滚 = 拷回备份）。
⚠️ **全局 dsh 升级会冲掉补丁** —— 升级后重跑 `~/.dsh/patch-web-token.sh` 即可，未打补丁时 env 被忽略、行为退回随机 token（安全降级）。

## 三、换 token / 停用方法

```bash
# 3081 轮换：删文件重启
rm ~/.dsh/run/dsh-web-dev.token && dsh-web-dev restart
# 3080 轮换：生成新值更新 plist 再重启
NEW=$(node -e 'process.stdout.write(require("crypto").randomBytes(32).toString("base64url"))')
plutil -replace EnvironmentVariables.DSH_WEB_TOKEN -string "$NEW" ~/Library/LaunchAgents/com.ygs.dsh-web.plist
launchctl bootout gui/$(id -u)/com.ygs.dsh-web; launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/com.ygs.dsh-web.plist
```

手机用法：在手机浏览器打开一次 `https://dsh-dev.want.biz/?token=<token 文件里的值>`（或 dsh.want.biz 对应 3080），登录后收藏**这个带 token 的地址**——以后重启服务它依然有效，点收藏即进。

## 四、验收记录（全部实测）

- 3081：restart 后日志 token == token 文件；再 restart 仍不变 ✓
- 3081 登录流：正确 token → 303 + cookie → 带 cookie 200；错误 token → 401 ✓
- 3080：launchctl kickstart 跨重启 token 不变 == plist 值 ✓；本机登录 303 ✓
- 隧道实测：`https://dsh.want.biz/?token=…` 与 `https://dsh-dev.want.biz/?token=…` 均返回 3xx 登录成功 ✓
- 排障备注：① token 行是服务 boot 后异步写日志的，脚本/自动化取日志验证要 sleep 几秒；② dev worktree 是多 agent 共享工作区，connection 包的 node 半由 **client face**（clientBundle）构建、host face 会跳过——改了 connection 源码要用 `pnpm exec tsdown --env.DSH_BUILD_FACE client`（包目录）重建，全量 `build:lib:host` 不覆盖它。
