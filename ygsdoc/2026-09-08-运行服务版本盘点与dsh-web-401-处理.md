## 二、dsh web 报 `authentication required; reopen the URL printed by dsh web` 是什么

**不是 bug，是 0.1.3-alpha.2 引入的 token 鉴权。**

- 启动日志（`~/.dsh/logs/dsh-web.log`）末尾会打印一行：
  `dsh web: http://127.0.0.1:3080/?token=<随机串>`
- 直接访问裸 `http://127.0.0.1:3080/`（无 token）会被鉴权中间件拦下，返回
  `HTTP 401 Unauthorized`，浏览器/CLI 提示上述 `authentication required` 文案。
- **token 每次启动重新生成、不持久化**（日志里能看到多次历史 token，对应多次启动/崩溃重启）。

### 正确处理方式（三选一）
1. **用启动日志里的带 token URL 访问**（最稳）：
   ```bash
   grep '?token=' ~/.dsh/logs/dsh-web.log | tail -1
   ```
   打开该行完整的 `http://127.0.0.1:3080/?token=...`（或 `http://dsh.want.biz/?token=...`）。
2. **重启并自动开浏览器**：`dsh-web restart`（脚本默认会 `open` 带 token 的 URL；若没自动开，按方式 1 取 token）。
3. **关掉鉴权（不推荐，仅本机可信网络）**：在 web profile 的 `cordis.yml` 关闭 auth 中间件——但 alpha.2 的 auth 是内建行为，需确认其配置键；生产/局域网暴露场景务必保留。

### 顺带发现的脚本小坑
`dsh-web.sh` 的 healthcheck 用 `curl http://127.0.0.1:$PORT/` 裸访问，alpha.2 下恒返回 401，被 `dsh-web status` 判为「不健康」。实际 3080 端口由 PID 8644 正常 LISTEN。**status 的 401 是脚本与 alpha.2 鉴权不兼容的误报，不影响真实访问**（带 token 即可进）。后续可给 healthcheck 加 `?token=` 或降级 401→视为健康。
