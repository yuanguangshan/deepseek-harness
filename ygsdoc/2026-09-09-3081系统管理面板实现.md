## 一、功能

3081 网页「设置」新增**系统管理**顶级分区（通用设置/模型/插件/Agent 预设之后）：

- **服务状态卡** ×3：dsh web 官方包（3080）、dsh web dev 构建（3081）、微信 ygs 链（8490）。每卡显示运行状态点、端口、PID、已运行时长、版本（官方包版本 / dev 分支@sha / weclaw 分支@sha）、进程命令行；8490 额外读 `/v1/status` 显示模型与忙碌态（如 `glm-5.3-flash · 空闲`）。10 秒自动刷新（host 侧 4s 快照缓存）。
- **重启**（两段式确认：首点武装 3 秒内再点执行）。3080/8490 走 `launchctl kickstart -k`（KeepAlive 自动拉起）；3081 走 detached `dsh-web-dev restart --force`（先应答后重启，页面 6 秒后自动 reload）。
- **日志**：每服务最近 N 行 tail（长行截断 500 字符，上限 300 行）。
- **带 token 访问地址**：每个 web 实例两条——本机 `127.0.0.1` + 隧道域名（**dsh.want.biz → 3080、dsh-dev.want.biz → 3081**，同 token），一键打开；8490 显示本机地址。

## 二、架构（为何这样做）

- **host 包** `packages/host/sysadmin`（`@deepseek-ai/dsh-host-sysadmin`）：cordis function plugin，`inject: ['connection']`，经 `ctx.connection.fetch.register` 挂 4 条 `/api/sysadmin/*` 精确路由（status/restart/logs/urls）。选这条路而非 `webServer.register` 是因为 **/api 通道自带 token→cookie 信任层**（file-upload 同款机制），裸访问 401 已实测；且对官方包 3080 同样可用。
- **client 包** `packages/client/ui-settings-sysadmin`：注册 `settings.section` slot（id `sysadmin`，order 90），`ctx.slots.inject` 注入 fetch API 面；`ctx.locale.register` zh/en 字典（zh 为 key 事实源）。**刻意不走 typert/remote 面**——省掉 api/remotes 挂载与代码生成，client 直接 fetch 同源 `/api`。
- **接线走 profile 层而非 web-app bundle**：两包在各自 package.json 声明 `dsh.bundle.patch`（`- insert:` 一行 roster），profile `package.json` 的 `dsh.profile.bundles` 追加两包名 + `dependencies` link: 到 dev worktree + `pnpm install`。**不动 `packages/bundle/web-app`、不动 api/remotes**——profile 是 3080/3081 共用的，这个层级的改动对两个 host 对称生效且可随时摘除（从 bundles 数组删掉即可）。dev 工作区源码零侵入（新包 + 无既有文件改动）。
- tsconfig：两包均**脱离仓库 composite 工程图**（host 包 paths 直指上游已构建 d.ts + `tsc --noEmit`；client 包宽松 emit 供 clientBundle 双半打包），避免 `tsc -b` 连锁重建 vendor 的坑。

## 四、注意事项与遗留

1. **重启后 token 轮换**（alpha.2 每次 boot 重新生成）：从面板重启 3081 后，浏览器旧 cookie 失效会停在认证页，需要从 `~/.dsh/logs/dsh-web-dev.log` 拿新 token URL 重新登录；重新进入后面板 URL 区展示的就是新地址。未来可考虑 token 持久化或重启后自动输出新 URL。
