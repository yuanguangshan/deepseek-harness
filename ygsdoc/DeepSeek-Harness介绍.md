# DeepSeek Harness：从聊天机器人到 AI Agent 操作平台的进化

> 本文介绍 DeepSeek Harness（DSH）——一个基于插件架构的 AI Agent 运行平台，它把大语言模型从"能聊天的工具"变成"能干活的智能体"。

---

## 一、问题：聊天机器人的天花板在哪里？

2024 年以来，大语言模型的能力飞速提升。从 GPT-4 到 DeepSeek V4，模型的推理能力、代码生成能力、多语言理解能力都在快速逼近人类专家水平。但有一个根本问题始终没有解决：**模型再聪明，也只能"说"，不能"做"。**

一个典型的场景：你问模型"帮我看看这个项目为什么启动失败"。模型会给你一堆可能的原因——依赖缺失、端口占用、配置错误——但它看不到你的项目文件，跑不了你的命令，也改不了你的代码。你只能把它输出的文字复制粘贴到终端里，手动验证每一条建议。

这不是模型的问题，而是**交互范式的问题**。聊天窗口是一个信息管道，不是一个工作平台。模型的知识被困在文字里，无法触及真实的文件系统、终端、远程服务器、数据库。

DeepSeek Harness 要解决的，正是这个问题。

---

## 二、DeepSeek Harness 是什么？

DeepSeek Harness（简称 DSH）是一个**插件化的 AI Agent 运行平台**。它的核心理念可以用一句话概括：**让大语言模型不仅能聊天，还能调用工具、读写文件、执行命令、管理远程服务器、调度任务。**

和普通的 ChatGPT 网页版不同，DSH 不是一个对话界面，而是一个**Agent 操作台**。它由三个核心层组成：

**模型层**：接入各种大语言模型——DeepSeek V4 Flash、V4 Pro、小米 mimo、SensNova 等。模型是大脑，负责推理和决策。

**工具层**：文件读写、终端执行、Git 操作、SSH 远程管理、视觉识别、网页搜索、微信推送……工具是手脚，负责执行模型的决策。

**平台层**：插件架构、会话持久化、任务调度、多模型路由、沙箱隔离、权限控制。平台是神经系统，连接大脑和手脚，管理生命周期。

这三个层组合在一起，就构成了一个完整的 Agent 系统：模型思考 → 工具执行 → 平台协调 → 人类监督。

## 三、架构：一切皆插件

DSH 最独特的地方在于它的架构设计。整个平台建立在一个叫 **Cordis** 的插件框架之上，核心原则只有一条：**一切皆插件。**

这意味着什么？模型适配器是插件，工具注册是插件，会话持久化是插件，Agent 循环本身也是插件。没有一个"核心"需要打补丁——你通过在旁边挂载新插件来扩展功能，注册都是副作用，插件卸载时自动回滚。

### 3.1 插件树与分层组合

一个运行中的 DSH 实例是一个**插件树**，在启动时由有序的层叠组合而成：

```
Profile（配置文件）
  ├── Bundle 1：dsh-base（基础层：模型适配器、工具、持久化、沙箱）
  ├── Bundle 2：dsh-web-app（Web 应用层）
  ├── Bundle 3：dsh-vision-router（视觉路由）
  ├── Bundle 4：dsh-ssh（远程服务器管理）
  ├── Bundle 5：dsh-task-board（任务看板）
  ├── cordis.patch.yml（用户自定义补丁）
  └── --patch overlay（命令行覆盖）
```

每一层都可以修改、禁用、或插入下层的配置。就像洋葱一样，你可以剥开任何一层来理解系统的行为，也可以在任何一层加上自己的补丁。

### 3.2 能力缝隙（Capability Seam）

DSH 的每个能力都遵循一个统一的三角色模式：

- **Service Definition**：定义能力的接口（做什么）
- **Service Provider**：实现能力的具体逻辑（怎么做）
- **Consumer**：把能力暴露给模型使用（怎么调用）

例如，文件系统能力：
- Definition：定义文件读写、搜索、glob 的接口
- Provider：本地文件系统实现（`dsh-fs-local`）
- Consumer：暴露给模型的 `read`、`write`、`edit`、`glob`、`grep` 工具

这种三角色分离意味着你可以换掉任何一层。想把本地文件系统换成远程 NFS？换 Provider 就行。想加一个审计层？在 Consumer 和 Provider 之间插入一个审计插件就行。

### 3.3 事件驱动

DSH 的扩展点是**事件**。每个插件通过 `ctx.effect()` 和 `ctx.on()` 注册自己的行为，而不是修改核心代码。

事件分为三类：
- **Session 事件**：持久化到日志的事实（如"用户发了一条消息"）
- **Agent 事件**：Agent 运行中的实时信号（如"开始执行一步"、"工具调用完成"）
- **Capability 事件**：能力层的策略和适配器挂载（如"文件系统权限变更"）

这种事件驱动的设计让 DSH 的每个组件都可以被替换、被观察、被拦截，而不需要修改其他组件。

## 四、核心能力：模型、工具与工作流

### 4.1 多模型支持

DSH 不绑定任何单一模型。它通过 `llm-pi-ai` 插件接入各种 OpenAI 兼容的 API，支持：

- **DeepSeek V4 Flash**：纯文本，1M 上下文窗口，便宜，适合日常文字对话
- **DeepSeek V4 Pro**：纯文本，更强的推理能力
- **SensNova 6.8 Flash-Lite**：视觉模型，支持图像输入，免费
- **小米 mimo-v2.5**：多模态，支持图像和文本
- **Weclaw 聚合网关**：接入几十种模型的统一接口

模型可以按场景切换：文字轮用便宜的 Flash，识图轮自动切到 SensNova，复杂推理用 Pro。用户在模型选择器里点一下就行，或者配置自动路由规则。

### 4.2 工具生态

DSH 内置了一套完整的工具体系，覆盖开发者日常工作的方方面面：

**文件操作**：`read`（读文件）、`write`（写文件）、`edit`（精确编辑）、`glob`（文件搜索）、`grep`（内容搜索）。所有文件操作都走沙箱策略，受权限控制。

**终端执行**：`bash`（执行命令）、`subagent`（委托子任务）。支持后台运行、超时控制、输出截断。

**Git 集成**：通过 SCM 面板直接 stage/unstage/discard 文件变更。Agent 改了十几个文件，你可以直接在右侧面板里逐个审查。

**视觉识别**：`vision_describe`（看图问答）、`vision_ocr`（文字识别）、`vision_ground`（像素定位）、`vision_crop`（裁剪放大）、`vision_pixel_diff`（像素对比）、`vision_colors`（取色）、`vision_trace`（SVG 矢量化）、`vision_extract_foreground`（抠图）。整套视觉工具链，覆盖从识图到像素级验证的全流程。

**远程管理**：通过 `dsh-ssh` 插件，Agent 可以 SSH 到远程服务器执行命令、上传下载文件、建立端口隧道、集群并发操作。

**任务调度**：通过 `dsh-task-board` 插件，支持多列看板管理任务，任务可以真实驱动 Agent 执行，支持 cron 定时调度。

**外部集成**：微信推送、知乎搜索、网页搜索、Kindle 发送等。

### 4.3 Agent 循环

Agent 循环是 DSH 的心脏。一次典型的交互流程：

```
用户输入
  ↓
Agent/pre-step（准备阶段）
  ↓
组装提示词 + 工具 Schema
  ↓
调用模型（llm/stream）
  ↓
模型返回文字 + 工具调用
  ↓
执行工具（tools/execute）
  ↓
工具结果返回模型
  ↓
模型继续推理（可能再调工具）
  ↓
最终输出给用户
```

一个"轮次"（turn）可能包含多个"步骤"（step），每个步骤是一次模型请求加它调用的工具。Agent 可以连续调用多个工具，形成推理链——比如先读文件、再搜索、再执行命令、再读结果、最后给出方案。

这个循环由 `agent-loop` 插件驱动，但你可以替换它。想用自定义的推理策略？写一个新插件替换 `agent-loop` 就行。

## 五、Web GUI：不只是聊天窗口

DSH 的 Web 界面（运行在 `127.0.0.1:3080`）远不止一个聊天窗口。它是一个完整的**Agent 工作台**，由多个面板组成：

### 5.1 聊天区

主区域是对话界面，支持 Markdown 渲染、代码高亮、图片预览。Agent 的每一步推理、每次工具调用、每个文件操作都会实时显示。

### 5.2 Explorer 面板

左侧的文件树，直接反映当前工作目录的真实文件系统。点击文件在预览面板打开，整行点击展开文件夹，支持按文件名搜索定位。

### 5.3 Preview 面板

右侧的多 tab 预览区，支持 Markdown、HTML、代码、Diff、CSV、PDF、Office 文档、图片、纯文本等格式。支持源码/预览切换、分屏编辑、保存。

### 5.4 SCM 变更面板

真实的 Git 操作面板。Agent 改了文件后，你可以直接在这里看到变更列表，选择 stage、unstage 或 discard。不需要切到终端跑 `git diff`。

### 5.5 模型选择器

切换当前会话使用的模型。支持按 provider 分组、按能力筛选（文本/视觉/推理）。

### 5.6 插件配置

Web 界面里可以直接修改插件配置，比如视觉路由的模型顺序、SSH 主机列表、任务看板设置。改完即时生效（部分需要重启）。

## 六、视觉系统：让 Agent 看见世界

DSH 的视觉系统是它最有趣的能力之一。通过 `dsh-vision-router` 插件，纯文本模型也能"看图"。

### 6.1 两条识图路径

**整轮路由**：当用户发送图片时，那一轮会自动切到视觉模型（如 SensNova），由视觉模型直接分析图片内容。文字轮保持原来的文本模型不变。

**视觉工具**：文本模型在对话中可以调用 `vision_describe` 等工具，由视觉模型在后台看图并返回文字描述。文本模型基于描述继续推理。

两条路径互补：整轮路由适合"看图说话"的场景，视觉工具适合"边聊边看"的场景。

### 6.2 视觉工具链

DSH 提供了一套完整的像素级视觉操作工具：

- `vision_describe`：看图问答，支持多图对比
- `vision_ground`：定位元素坐标
- `vision_detect`：检测图像中的元素
- `vision_crop`：裁剪放大指定区域
- `vision_pixel_diff`：像素级对比验证
- `vision_colors`：取色分析
- `vision_ocr`：文字识别
- `vision_trace`：SVG 矢量化
- `vision_extract_foreground`：抠图
- `vision_html_screenshot`：网页截图

这些工具让 Agent 不仅能"看"图片，还能做像素级的精确操作——比如对比两张设计稿的差异、从截图中提取文字、验证 UI 元素的位置。

### 6.3 模型包装（Wrapped Providers）

DSH 的一个巧妙设计是**模型包装**。纯文本模型（如 DeepSeek V4 Flash）本身不支持图像输入，但通过 `wrappedProviders` 机制，它可以被包装成一个"自动识图"孪生路由。

这个孪生路由的作用不是让纯文本模型真正看图（它做不到），而是让它能**挂在图片上下文里不报错**。图片本身由视觉模型在后台处理，文本模型基于视觉模型的文字描述继续工作。

这意味着：你可以在同一个会话里，文字轮用便宜的 DeepSeek，图片轮自动切到 SensNova，两者无缝协作。

## 七、远程管理：Agent 的手脚延伸到服务器

`dsh-ssh` 插件让 Agent 的能力不再局限于本机。通过 SSH，Agent 可以操作任何你配置好的远程服务器。

### 7.1 核心能力

- **主机管理**：从 `~/.ssh/config` 导入主机配置，支持密钥/密码认证、passphrase、ProxyJump 跳板机
- **命令执行**：在远程服务器上执行任意命令，支持超时控制
- **文件传输**：上传/下载文件，支持大文件
- **端口隧道**：建立本地端口转发，访问远程数据库、内网服务
- **集群并发**：同时在多台服务器上执行命令，支持并发控制

### 7.2 使用场景

一个典型的场景：你需要在 5 台生产服务器上检查磁盘空间。以前你需要逐台 SSH 上去执行 `df -h`，现在只需要告诉 Agent：

> "检查所有生产服务器的磁盘空间"

Agent 会自动：
1. 读取 SSH 配置，找到所有生产服务器
2. 并发执行 `df -h`
3. 汇总结果，标记异常
4. 给你一份清晰的报告

另一个场景：你需要把一个配置文件部署到 3 台服务器。Agent 可以：
1. 读取本地配置文件
2. 上传到每台服务器
3. 重启相关服务
4. 验证服务状态

整个过程无需你手动 SSH 到任何一台服务器。

### 7.3 安全约束

DSH 对远程操作有严格的安全约束：
- 所有远程操作由用户在 GUI 中配置后 Agent 才能使用
- 密码以明文存在用户主目录私有文件（权限 0600）
- 命令输出原样返回，可能含敏感信息
- 断线重连可能重放非幂等命令
- 传输/执行消耗真实远程资源，先确认再操作

## 八、任务系统：从一次性对话到持续工作

`dsh-task-board` 插件把 DSH 从"一问一答"的对话模式提升到"持续工作"的任务模式。

### 8.1 多列看板

任务看板支持多列管理：

```
待处理 → 执行中 → 验证中 → 已完成
```

每个任务可以关联一个 Agent 会话，点击"执行"就会驱动 Agent 完成任务。

### 8.2 定时调度

任务支持 5 段 cron 表达式定时执行。例如：

- `0 23 * * *`：每天 23:00 执行
- `*/30 * * * *`：每 30 分钟执行
- `0 9 * * 1-5`：工作日 9:00 执行

定时任务在浏览器端调度，需要 GUI 标签页保持打开。

### 8.3 任务驱动 Agent

任务不是简单的 Todo List。点击"执行"后，任务会创建一个真实的 Agent 会话，驱动模型完成任务。这意味着：

- 任务可以读取文件、执行命令、调用工具
- 任务结果会持久化到会话日志
- 任务可以被暂停、恢复、取消

## 九、配置与定制

DSH 的配置是分层的，从底层到顶层：

### 9.1 Settings（用户设置）

`~/.dsh/settings.yaml` 是用户级配置，控制：

- 默认模型（`agent-default-model`）
- LLM Provider（`llm-pi-ai`）
- UI 偏好（主题、语言、侧边栏）
- 插件特定配置

### 9.2 Profile（配置文件）

`~/.dsh/profiles/web/` 是 Web profile 的配置目录：

- `package.json`：声明依赖的插件包
- `cordis.patch.yml`：补丁层配置，覆盖下层的插件配置
- `cordis.yml`：合成后的最终配置（由 DSH 自动生成）

### 9.3 环境变量

`.env` 文件存储 API Key 等敏感信息：

```
DEEPSEEK_API_KEY=sk-xxx
SENSENOVA_API_KEY=sk-xxx
ARK_API_KEY=xxx
```

### 9.4 插件配置

每个插件都可以通过 `cordis.patch.yml` 的补丁层配置。例如，视觉路由的模型顺序：

```yaml
- id: vision-router
  config:
    providers:
      - provider: vision-http
        model: sensenova/sensenova-6.8-flash-lite
    httpProviders:
      - name: sensenova
        baseURL: https://token.sensenova.cn/v1
        model: sensenova-6.8-flash-lite
        apiKeyEnv: SENSENOVA_API_KEY
```

DSH 不仅是一个产品，也是一个开发平台。它为开发者提供了完整的工具链：

### 10.1 从源码运行

```bash
pnpm install
pnpm run build
pnpm dsh --profile web
```

### 10.2 测试

```bash
pnpm run test          # 单元测试
pnpm run test:e2e      # 端到端测试（需要 API Key）
pnpm run test:snapshot # 快照测试
```

### 10.3 插件开发

开发一个新插件只需要：

1. 在 `packages/` 下创建一个新包
2. 实现 `apply(ctx, config)` 函数
3. 在 `package.json` 里声明 `dsh.bundle.patch`
4. 在 profile 的 `package.json` 里添加依赖

插件可以贡献工具、模型适配器、事件监听器、UI 组件——任何 Cordis 支持的能力。

## 十三、总结：Agent OS 的雏形

DeepSeek Harness 不只是一个"更好的聊天界面"。它是一个**Agent 操作平台**的雏形——把模型的大脑、工具的手脚、平台的神经网络组合成一个完整的智能体系统。

它的核心价值不在于某个单一功能，而在于**组合方式**：

- 模型 + 文件系统 = 能读写代码的 Agent
- 模型 + 终端 = 能执行命令的 Agent
- 模型 + SSH = 能管理远程服务器的 Agent
- 模型 + 视觉 = 能看图分析的 Agent
- 模型 + 任务调度 = 能持续工作的 Agent
- 模型 + 插件架构 = 能自我进化的 Agent

当你把这些组合排列起来，你会发现 DSH 正在回答一个更大的问题：
