## 3. 核心代码解析

### 3.1 五条轨道与存储位置（`memory.ts` L30–78）

```ts
export type MemoryTarget = 'memory' | 'user' | 'daily' | 'project' | 'key'
```

存储在 `~/.dsh-repl/memory/`（可用 `DSH_REPL_MEMORY_DIR` 覆盖）：

| 轨道 | 文件 | 作用域 |
|------|------|--------|
| `memory` | `MEMORY.md` | 长期记忆，跨项目（→ 快照中的 `## 长期记忆（跨会话，始终遵守）`）|
| `user` | `USER.md` | 用户档案，跨项目（→ `## 用户档案`）|
| `daily` | `daily/YYYY-MM-DD.md` | 每日日志，按项目打标 |
| `project` | `projects/<hash>/MEMORY.md` | 项目日志 |
| `key` | `projects/<hash>/KEY.md` | 项目关键记忆（→ `## 本项目的关键记忆`），按 git 分支过滤 |

项目 id 通过对规范化 `cwd` 做 **SHA-1 → 前 12 位 hex** 生成：

```ts
export function projectHash(cwd: string): string {
  const normalized = cwd.replace(/\\/g, '/').replace(/\/+$/, '')
  return createHash('sha1').update(normalized).digest('hex').slice(0, 12)
}
```

### 3.2 条目分隔与序列化（L26–105）

条目之间用 `\n§\n` 分隔，纯函数往返可测：

```ts
export const ENTRY_DELIMITER = '\n§\n'

export function parseEntries(text: string): string[] {
  return text.split(ENTRY_DELIMITER).map(e => e.trim()).filter(e => e !== '')
}
export function serializeEntries(entries: readonly string[]): string {
  return entries.join(ENTRY_DELIMITER) + (entries.length > 0 ? '\n' : '')
}
```

### 3.3 日期与 git 打戳（L137–184）

- **长期轨道（memory/user）**：只加 `[YYYY-MM-DD]` 日期前缀，**幂等**（已带日期则不重复加）。
- **project/key**：加 `[YYYY-MM-DD HH:MM]` 精确到分钟，并附 `[git <分支>]` 标签。
- **daily**：加 `[HH:MM]` 时间戳 + `[<项目标签>]` 项目名 + `[git <分支>]`。

```ts
function stampLongTerm(content: string, now: Date): string {
  if (/^\[\d{4}-\d{2}-\d{2}\]\s/.test(content)) return content
  return `[${todayStamp(now)}] ${content}`
}
```

### 3.4 `MemoryStore` 类（L190–259）

核心存储类，五个方法：

- **`readRaw`** — 读取轨道原始文本（文件不存在返回空串）；
- **`entriesOf`** — 返回解析后的条目；对 `key` 轨道在启用 `keyBranchFilter` 且处于 git 工作区时，按当前分支过滤 `[branch:...]` 作用域；
- **`write`** — 整体覆写轨道内容，自动 `mkdirSync` 建父目录；
- **`add`** — 打戳后追加；**精确重复自动去重**（`entries.includes(stamped)` 跳过）；
- **`remove`** — 删除包含 `needle` 的条目，返回删除数量。

关键去重与写入：

```ts
add(target: MemoryTarget, content: string, cwd?: string, now: Date = new Date()): void {
  const { stamped } = stampEntry(target, content, cwd, now, cfg)
  const entries = parseEntries(this.readRaw(target, cwd))
  if (entries.includes(stamped)) return  // 幂等去重
  entries.push(stamped)
  this.write(target, entries, cwd)
}
```

### 3.5 快照渲染 — 记忆如何"喂给"AI（L285–303）

`renderMemorySnapshot` 把 memory/user/key 三条全局轨道渲染成 Markdown，逐条 `- ` 前缀、每条截断到 160 字符（`maxEntry` 可调），并限制数量（memory 12 / user 8 / key 12）：

```ts
export function renderMemorySnapshot(opts: MemorySnapshotOptions): string {
  const cap = opts.maxEntry ?? 160
  if (mem.length > 0)
    parts.push(`## 长期记忆（跨会话，始终遵守）\n${mem.map(e => `- ${clamp(e, cap)}`).join('\n')}`)
  if (user.length > 0)
    parts.push(`## 用户档案\n${user.map(e => `- ${clamp(e, cap)}`).join('\n')}`)
  if (key.length > 0)
    parts.push(`## 本项目的关键记忆${branchHint}\n${key.map(e => `- ${clamp(e, cap)}`).join('\n')}`)
  return parts.join('\n\n')
}
```

这正是我们在 REPL 会话中每次看到的那段记忆上下文的来源：

```markdown
## 长期记忆（跨会话，始终遵守）
- [2026-08-15] 我叫广山哥

## 用户档案
- [2026-08-15] 思考时请用中文
```

### 3.6 TUI 集成 — prompt 注入（`tui-repl.ts` L1124–1126）

每次提交输入时，快照作为一个显式的记忆上下文拼在用户输入之前：

```ts
const injection = memorySnapshot()
const promptText = injection !== ''
  ? `[长期记忆上下文]\n${injection}\n\n请在此基础上作答。用户输入：${t}`
  : t
await client.prompt(sessionId, [{ type: 'text', text: promptText }])
```

**关键点**：有记忆才注入（no-op when empty），因此在没有记忆时对性能、上下文长度都几乎无影响。

### 3.7 `/memory` 命令家族与自动日志（L258–294, L1170–1175）

| 命令 | 行为 |
